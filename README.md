touchscreen app, but the whole machine firmware stack: a rebuilt on-device touchscreen
control UI and a corrected main-controller firmware, covering 3D printing / laser
engraving / CNC machining, running on the Artisan's built-in 7-inch touchscreen.

## What is this?

Two cooperating firmware layers live inside the Artisan: a **touchscreen UI** — everything
you see and touch on the panel — and a **Marlin-customized main controller firmware** on
the motion board, the layer that actually moves the machine, heats it, and runs your jobs.
Snapmaker has published the sources of both layers. This project rebuilds the pair from
the ground up:

- **Screen side**: a cleaned-up, A400-only codebase, a fully redesigned interface, and a
  machine-command channel that has been systematically audited and backed by automated
  tests;
- **Main controller side**: upstream Marlin fixes backported, protocol parsers hardened,
  and motion-safety fixes — wherever a bug lives, it gets fixed in that layer, never
  papered over in the UI.

The final package flashes as a standard firmware update package built to the same
specifications as the factory original — **no hardware modifications required**.

## Project goals

1. **Travel light.** Cut legacy multi-model support (J1 / A350) and every dead branch that
   came with it, putting all engineering effort into the Artisan.
2. **A modern, consistent touch UI.** Replace screen-by-screen patchwork with a real design
   system (component library + multi-theme + multi-language system).
3. **Fix the whole stack, not the symptoms.** Screen and controller are treated as one
   product: defects are fixed in the layer where they live, and both sides ship together as
   one package.
4. **Testable safety.** Every machine-bound command on the screen side (FDM / laser / CNC)
   is generated by pure functions with byte-level unit tests; the controller's parsers and
   motion paths are hardened — the command surface is audited end-to-end instead of patched
   ad hoc.
5. **Hardware-free development.** An emulator + physical test bench lets the entire UI and
   most workflows be developed and verified with no printer attached.
6. **Open and sustainable.** Fully open-sourced with a well-documented architecture — a
   codebase contributors can actually maintain for the long run.

## Key improvements so far

### Screen side — the control app (Android)

- **A400-only core refactor** — legacy model branches removed at the code level, cutting
  app size and complexity by ~52%.
- **Design system v3** — shared UI component library + per-component specifications, with
  a built-in multi-language system (currently English / 简体中文 / Deutsch).
- **Redesigned core workflows** — home, print preparation, laser and CNC job flows, plus a
  new guided homing page with live machine/work coordinate readouts.
- **Jog & coordinate system rework** — a reliable jog control panel (XY / Z / rotary /
  numeric entry), go-to-position with dynamic legality checks, and guided Z touch-off /
  probe calibration flows.
- **Bluetooth gamepad control mapping** — pair a Bluetooth gamepad and map its buttons to
  machine control, for predictable, handwheel-like operation.
- **Laser safety key** — no more typing laser verification codes over and over:
  authorization is based on a USB-drive key, while the drive's normal file read/write
  functionality stays intact.
- **Command-layer safety audit** — all FDM/laser/CNC outbound payloads are built by pure
  functions with byte-level unit tests; the async pipeline gets global error handling;
  firmware-safety fixes (soft-limit handling, focus-range cap, etc.).
- **Smart file screening** — files are labeled per tool head (3DP / laser / CNC), and
  inapplicable files are intercepted before a job starts.
- **Multi-file-format support** — print files from multiple slicers (Luban / OrcaSlicer /
  LightBurn) are recognized and handled in one place.
- **Multi-plate 3MF support** — 3MF files containing multiple plates are supported.
- **Hardware-free development pipeline** — emulator + physical test bench for daily UI
  verification, with layout-binding and unit-test gates before any build ships.
- **Streaming jog rework (in progress)** — during tool touch-off, commands are queued with
  instant cancellation, making manual control feel dramatically better.

### Main controller side — the motion board (Marlin-based)

- **Upstream Marlin fix backports** — accepted upstream Marlin bug fixes backported in
  batches to the Artisan's firmware baseline (2.0.x → 2.1.x).
- **Protocol parser hardening** — infinite loops and length underflows fixed in the
  controller's serial protocol parsing, so malformed data can no longer wedge the board.
- **Defensive hardening pass** — null guards, boundary checks and exception-path fixes
  across the controller code, plus SACP result-cache, module-pointer-lifecycle and
  motion-path guard fixes.
- **Motion-safety fixes** — e.g. during manual bed leveling, the lift between probe points
  could be clamped into a downward press and drive the nozzle into the bed when a tall
  gauge block is used.

## Can I flash the preview on my machine?

The preview ships as a **complete firmware update package covering both the screen side
and the main controller**, installed through the Artisan's standard update flow.
Requirements and caveats:

- **Artisan (A400) only** — other Snapmaker models are not supported.
- **Snapmaker 2.0 tool heads are not supported** (single-extruder / 1.6W laser, etc.).
- **It replaces the official firmware on both the screen and the controller board.** This
  is a preview: expect bugs.
- **Both the preview and the final release can be rolled back to the official firmware at
  any time** — but only by flashing from a USB drive; the exact steps will be explained in
  the install guide.
- Install instructions will be published together with the preview download.
